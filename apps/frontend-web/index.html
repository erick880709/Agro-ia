🔗 API de sensores — simulador de trama

Conexión real de los sensores: POST /api/sensor. El firmware envía un JSON con device_id obligatorio y estos campos: ph (0–14), nitrogen, phosphorus y potassium (ppm), conductivity (µS/cm), humidity (% HR ambiente, DHT22), temperature (°C ambiente), rssi (dBm) y uptime_s (s). finca_id (UUID) asocia el dispositivo a tu finca, y latitude/longitude (grados decimales WGS84) registran el punto de muestreo para el mapa de calor. Si el device_id no está registrado, el API lo auto-registra. Pega una trama y pruébala:

📂 Carga manual de mediciones (cuando el sensor pierde conexión)

Adjunta un archivo CSV, TXT o JSON con las mediciones. La aplicación lo lee, normaliza las unidades (µS/cm → dS/m), persiste la lectura y genera la recomendación al instante.

🗂️ Carga masiva — historial de ciclos (CSV) (grandes fincas · últimos 5 años)

Sube un CSV con el historial de ciclos del predio. Columnas: lote, cultivo, fecha_siembra, fecha_cosecha, rendimiento, aplicaciones_texto. El lote se crea si no existe, el rendimiento queda en t/ha y el texto de aplicaciones («Urea 150kg, DAP 80kg») se convierte a JSONB.
